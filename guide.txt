# Push Notifications for a Two-App System (PWA → Admin Dashboard)

## The Problem

You have two separate web applications:
- **Employee PWA** — where sales are made and synced to a shared database
- **Admin Dashboard** — where the admin wants to receive notifications about new sales

They share the same backend and database. You want the admin to get a notification on their device when a sale occurs on the employee's PWA.

Chrome's "Send to your devices" feature is **not replicable** from a third-party app — it's an internal Chrome Sync feature tied to a Google Account with no public API.

---

## Option 1: Web Push API (Raw)

### How it works

```
[Employee PWA]          [Your Backend]           [Push Service]           [Admin's Device]
     │                    │                       │                        │
     │── sale ──────────▶│                       │                        │
     │   (sync to DB)    │                       │                        │
     │                    │── push to endpoint ──▶│                        │
     │                    │   (stored sub)        │── deliver message ────▶│
     │                    │                       │                        │
     │                    │                       │         browser wakes  │
     │                    │                       │         service worker │
     │                    │                       │         shows notif    │
```

You never send directly to the device. The push service (Google's FCM for Chrome, Mozilla's for Firefox) is a third-party relay. Your server → push service → admin's browser.

### Frontend (Admin Dashboard)

```js
// After successful auth:
async function enableNotifications() {
  const reg = await navigator.serviceWorker.register('/sw.js');
  const sub = await reg.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: urlBase64ToUint8Array('YOUR_VAPID_PUBLIC_KEY')
  });
  await fetch('/api/save-subscription', {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${token}` },
    body: JSON.stringify({ ...sub, role: 'admin' })
  });
}
```

### Service Worker

```js
// sw.js
self.addEventListener('push', (event) => {
  const data = event.data.json();
  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
      data: { url: data.url }
    })
  );
});
```

### Backend (Node.js Express)

```js
const webpush = require('web-push');

webpush.setVapidDetails(
  'mailto:you@example.com',
  'YOUR_VAPID_PUBLIC_KEY',
  'YOUR_VAPID_PRIVATE_KEY'
);

// On sale:
app.post('/sale', async (req, res) => {
  await db.insert('sales', req.body);

  const adminSubs = await db.query(
    "SELECT endpoint, p256dh, auth FROM subscriptions WHERE role = 'admin'"
  );

  for (const sub of adminSubs) {
    await webpush.sendNotification(sub, JSON.stringify({
      title: 'New Sale',
      body: `${req.body.customer} — $${req.body.amount}`,
    }));
  }

  res.json({ ok: true });
});
```

### Database Schema

```sql
CREATE TABLE subscriptions (
  id SERIAL PRIMARY KEY,
  user_id INT NOT NULL,
  role VARCHAR(20) NOT NULL,       -- 'employee' or 'admin'
  endpoint TEXT NOT NULL,
  p256dh TEXT NOT NULL,
  auth TEXT NOT NULL,
  user_agent TEXT
);
```

## Option 2: FCM (Firebase Cloud Messaging)

### How it works

Same concept as Web Push, but Firebase handles the relay. You get a **registration token** per device instead of a raw subscription endpoint.

```
[Employee PWA]          [Your Backend]            [FCM Server]            [Admin Dashboard]
     │                        │                       │                         │
     │── POST /sale ────────▶│                       │                         │
     │                        │── admin.messaging()  │                         │
     │                        │   .send({token}) ───▶│── deliver ─────────────▶│
     │                        │                       │                         │
     │                        │                       │              SW wakes, shows notif
```

### React Admin Dashboard

```js
// src/firebase.js
import { initializeApp } from "firebase/app";
import { getMessaging, getToken, onMessage } from "firebase/messaging";

const app = initializeApp({
  apiKey: "YOUR_API_KEY",
  projectId: "YOUR_PROJECT_ID",
  messagingSenderId: "YOUR_SENDER_ID",
});

export const messaging = getMessaging(app);
```

```js
// After login:
import { messaging } from "./firebase";
import { getToken } from "firebase/messaging";

navigator.serviceWorker.register("/firebase-messaging-sw.js");

async function enableNotifications() {
  const token = await getToken(messaging, { vapidKey: "YOUR_VAPID_KEY" });
  await fetch("/api/save-fcm-token", {
    method: "POST",
    headers: { "Authorization": `Bearer ${authToken}` },
    body: JSON.stringify({ fcmToken: token, role: "admin" }),
  });
}
```

```js
// public/firebase-messaging-sw.js
importScripts("https://www.gstatic.com/firebasejs/10.7.1/firebase-app-compat.js");
importScripts("https://www.gstatic.com/firebasejs/10.7.1/firebase-messaging-compat.js");

firebase.initializeApp({ /* same config */ });
const messaging = firebase.messaging();

messaging.onBackgroundMessage((payload) => {
  self.registration.showNotification(
    payload.notification.title,
    { body: payload.notification.body }
  );
});
```

### Backend (Node.js Express)

```js
const admin = require("firebase-admin");
const express = require("express");
const app = express();

admin.initializeApp({
  credential: admin.credential.cert(require("./serviceAccountKey.json")),
});

app.post("/sale", async (req, res) => {
  await db.insert("sales", req.body);

  const adminTokens = await db.query(
    "SELECT fcm_token FROM subscriptions WHERE role = 'admin'"
  );

  for (const { fcm_token } of adminTokens) {
    await admin.messaging().send({
      token: fcm_token,
      notification: { title: "New Sale", body: `$${req.body.amount}` },
    });
  }

  res.json({ ok: true });
});
```

### Safari Support (as of 2023+)

| Platform | Version | Requirement |
|---|---|---|
| macOS Safari | 16.1+ | None |
| iOS / iPadOS Safari | 16.4+ | Must be added to Home Screen (PWA) |

Use `isSupported()` to check before subscribing:

```js
import { isSupported, getMessaging } from "firebase/messaging";

if (await isSupported()) {
  const token = await getToken(messaging, { vapidKey: "..." });
} else {
  // Fallback: WebSocket or in-app polling
}
```

## Option 3: WebSocket

### How it works

No push service, no tokens, no service worker. The admin dashboard keeps a **persistent connection** open to your server.

```
[Employee PWA]          [Your Backend]              [Admin Dashboard]
     │                        │                           │
     │── POST /sale ────────▶│                           │
     │                        │── ws.send({type:'sale'}) ─▶│
     │                        │   (to admin's socket)     │  shows in-app
     │                        │                           │  banner / toast
```

### Admin Dashboard (Client)

```js
// After auth:
const ws = new WebSocket(`wss://yourapp.com/ws?token=${authToken}`);

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.type === 'new_sale') {
    showInAppNotification(msg);
  }
};

ws.onclose = () => {
  setTimeout(connect, 3000); // Reconnect with backoff
};
```

### Backend (Node.js Express)

```js
const { WebSocketServer } = require('ws');
const wss = new WebSocketServer({ server, path: '/ws' });

const adminSockets = new Set();

wss.on('connection', (ws, req) => {
  const token = new URL(req.url).searchParams.get('token');
  const user = verifyToken(token);

  if (user.role === 'admin') {
    adminSockets.add(ws);
  }

  ws.on('close', () => adminSockets.delete(ws));
});

app.post('/sale', async (req, res) => {
  await db.insert('sales', req.body);

  const payload = JSON.stringify({
    type: 'new_sale',
    customer: req.body.customer,
    amount: req.body.amount,
  });

  for (const ws of adminSockets) {
    if (ws.readyState === 1) ws.send(payload);
  }

  res.json({ ok: true });
});
```

## Service Worker Registration & Auth Gating

The service worker is just JavaScript that *you* call. You control exactly when it registers:

```
[Someone opens the URL]
        │
        ▼
[Show code-entry screen]  ← no service worker here
        │
        ▼
[Code verified, user logged in as admin]
        │
        ▼
[Dashboard loads]
        │
        ▼
[Register SW + subscribe + send subscription to backend]  ← only NOW
```

- `/sw.js` must be publicly accessible (no auth on the file itself)
- The *call* to `register()` is what you gate behind auth
- Each new device = new subscription
- Multiple admins on multiple devices = multiple rows in your subscriptions table

### Multiple apps on the same domain

| Setup | SW files | Subscriptions per device |
|---|---|---|
| Both at root, one shared SW | `/sw.js` | 1 (tagged by role in DB) |
| Separate paths | `/sw-employee.js`, `/admin/sw-admin.js` | 2 (independent) |
| Separate domains | One per domain | 2 (independent) |

**Rule:** One service worker per scope per origin. Two different SW files for the same scope = the second overwrites the first.

## VAPID (Voluntary Application Server Identification)

A **public/private key pair** (ECDSA P-256) that authenticates your server to the push service.

| Key | Where it lives | What it does |
|---|---|---|
| Public key | Shared with browser at subscribe time | Stored by push service; verifies your signature |
| Private key | Secret, on your backend only | Signs every push request |

### Why it exists

The push service needs to verify **who is sending the message**. Without VAPID, anyone who steals a subscription endpoint could send notifications to your users.

### Generate keys

```js
const webpush = require('web-push');
const { publicKey, privateKey } = webpush.generateVAPIDKeys();
```

```bash
npx web-push generate-vapid-keys
```

### Key points

- VAPID does **not** encrypt message content (that's handled by `p256dh`/`auth` keys)
- Chrome and Safari **require** VAPID
- Generate once, reuse for all subscribers
- FCM handles VAPID for you (you just provide a VAPID key to `getToken()`)

## Costing

| Option | Notification cost | What you'd pay for |
|---|---|---|
| Web Push (raw) | $0 | Your existing server |
| FCM | $0 (unlimited, free on Spark and Blaze) | Your existing server + free Firebase project |
| WebSocket | $0 | Your existing server |

No per-message fees, no tiered pricing. You're already running a Node.js Express backend — all three options use that same server.

---

## Recommendation

| Need | Best option |
|---|---|
| Admin might have browser closed | **Web Push** or **FCM** |
| Admin always has dashboard open | **WebSocket** (simplest) |
| Want to avoid managing VAPID keys | **FCM** |
| Need reliable Safari iOS support | **Web Push** (raw) |
| Want instant delivery + offline fallback | **WebSocket + Web Push** (hybrid) |
